# Задание 3 — Оптимизация boxing/unboxing

**Проект:** `Lab4/Task3` · **Запуск:** `cd Lab4/Task3 && dotnet run`

## Что делает программа

Измеряет стоимость упаковки `int` в `object` и показывает, как её убрать.
Все замеры аллокаций сделаны точным методом
`GC.GetTotalAllocatedBytes(precise: true)`.

## 3.1. Сравнение производительности

```
  List<object> (упаковка)                 84.04 мс      38.90 МБ  сборок Gen0: 5
  List<object> (упаковка), прогрев        78.33 мс      38.89 МБ  сборок Gen0: 4
  List<int>    (без упаковки)              5.06 мс       8.00 МБ  сборок Gen0: 0
```

Арифметика, которую стоит показать преподавателю:

- 1 упакованный `int` = **24 байта** (8 байт значение + 16 байт заголовок объекта).
- 1 000 000 × 24 = **24 000 000 байт ≈ 22,89 МБ** — это чистый мусор от упаковки.
- `List<int>` хранит данные в типизированном массиве: 4 МБ на миллион + 4 МБ роста
  массива при удвоении ≈ 8 МБ с запасом.
- Итого 8,00 + 22,89 ≈ 30,9 МБ, но `List<object>` показывает 38,89 МБ, потому что
  массив ссылок (`8 × 1 000 000 = 8 МБ`) заменяет массив `int`.

Разница аллокаций — **4,9 x**, разница времени — **9,4 x**.

Сборки Gen0 (4–5 против 0) подтверждают: упакованные объекты — мусор, который
приходится собирать.

## Как измерять аллокации правильно

```csharp
long before = GC.GetTotalAllocatedBytes(precise: true);
Work();
long allocated = GC.GetTotalAllocatedBytes(precise: true) - before;
```

**`precise: true` обязателен.** Без него метод по умолчанию читает счётчик
приблизительно (базовый счётчик потоков) и результат может отличаться на
проценты или вообще показывать ноль.

**Нужен вызов вне измеряемого участка.** Счётчик не привязан к потоку — он
глобальный, поэтому любые аллокации других потоков попадут в измерение.
Программа измеряет в однопоточной части, поэтому результат стабилен.

## 3.2. Оптимизация существующего кода

```
  UnoptimizedCode.Add -> ArrayList   63.26 мс      38.89 МБ  сборок Gen0: 3
  OptimizedCode.Add -> List<int>      6.72 мс       8.00 МБ  сборок Gen0: 0
```

Оба класса идентичны по интерфейсу — меняется только тип поля
(`ArrayList` → `List<int>`), что убирает упаковку.

### Чтение: unboxing не аллоцирует, но стоит времени

```
  Чтение из ArrayList (с unboxing): 68.71 мс, сумма 4999995000000
  Чтение из List<int>  (без него):  46.13 мс, сумма 4999995000000
  Ускорение: 1.49 x
  Важно: сам unboxing НЕ выделяет память — он лишь копирует значение и проверяет тип.
```

Unboxing не создаёт объект, он лишь читает значение из существующего. Замедление —
из-за проверки типа на каждом элементе и запрета некоторых JIT-оптимизаций.

## Скрытая упаковка при переборе

```
  foreach по IEnumerable (объектная версия): аллокаций 24000384 байт
  foreach напрямую по List<int>:             аллокаций 0 байт
  Причина: IEnumerable — объектный интерфейс, поэтому перечислитель упаковывается,
  а int внутри foreach(object) приходится приводить обратно.
```

Это важный практический вывод: `foreach` по `List<int>` через `IEnumerable<T>`
в .NET обобщённый и не аллоцирует, а вот `IEnumerable` (не-обобщённый) —
аллоцирует. `List<int>` как `IEnumerable` заставляет интерфейс перечисления
упаковываться. **24 000 384 байта** — это ровно 1 000 000 × 24 байта, то есть
упакованные перечислители.

## Ловушка, найденная при замерах: `GC.KeepAlive` упаковывает `int`

```
  GC.KeepAlive имеет сигнатуру KeepAlive(object), поэтому вызов
  GC.KeepAlive(temp) с переменной типа int САМ создаёт объект 24 байта.
  Первая версия этого замера показала одинаковые 240 000 байт в обоих циклах.
```

`GC.KeepAlive` принимает `object`:

```csharp
public static void KeepAlive(object obj);
```

Поэтому `GC.KeepAlive(temp)`, где `temp` — `int`, **неявно упаковывает** его, и
измерение «оптимизированного» варианта показывает столько же аллокаций, сколько
неоптимизированный. Первая версия замера именно так и ошиблась.

Правильный способ — передать точно ссылочный тип:

```csharp
GC.KeepAlive(sink);   // sink — поле-ссылка на объект, упаковки нет
```

Это хороший пример того, что **измеритель может врать**: инструмент измерения
сам introduces аллокацию и искажает результат. Все замеры в лабораторной работе
сделаны с проверкой на отсутствие такого эффекта.
