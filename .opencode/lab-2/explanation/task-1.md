# Задание 1 — Базовые примеры утечки памяти

**Файл:** `Lab2/Task1/Program.cs`
**Целевая платформа:** .NET 10.0 (SDK 10.0.401)

## Суть задания

Выполнить и объяснить базовые примеры утечки памяти: статические ссылки,
событийные утечки, Large Object Heap (LOH) и упаковки/распаковки (boxing).

## Что делает программа

**Часть 1. Наглядная демонстрация «статика vs экземпляр»**

- `StaticReferenceDemo` — статическое поле `_staticList` одно на все объекты;
  модификация через любой объект видна остальным. Экземплярное поле
  `_instanceList` своё у каждого.
- `StaticFieldDemo` — то же самое на счётчиках.

Результат (после `obj1.AddToStatic(100)`, `obj2.AddToStatic(200)`,
`obj3.AddToStatic(300)`):

```
Объект 1: статический [100, 200, 300], экземплярный [1]
Объект 2: статический [100, 200, 300], экземплярный [2]
Объект 3: статический [100, 200, 300], экземплярный [3]
```

**Часть 2. Основная демонстрация утечек**

1. `AllocateMemory(10)` — 10 МБ в обычной куче (SOH) +
   `AllocateLOHObjects(100)` — 100 объектов LOH (> 85 КБ).
2. `MemoryLeakExample.CreateMemoryLeak()` — 1000 × 10 КБ в статическом
   списке (объекты недостижимы из кода, но удерживаются статическим корнем);
   `EventLeakExample.SubscribeLeak()` ×100 — подписка без отписки.
3. `SimulateBoxing(1_000_000)` — упаковка `int` в `object` (замер времени).
4. `ClearMemoryLeak()` + `Cleanup()` + `GC.Collect()` — освобождение.
5. Поколения: новый объект = Gen0, после `GC.Collect()` = Gen1.

## Наблюдаемые результаты

```
Total Memory: 18 MB (1) → 28 MB (2) → 4 MB (после очистки)
Время с упаковкой (List<object>): 112ms, без упаковки (List<int>): 7ms
Начальное поколение: 0, после GC.Collect(): 1
```

## Почему это утечки

| Механизм | Причина |
|----------|---------|
| Статическая коллекция | статическая ссылка — корень GC, живёт всё время жизни домена |
| Событие | поле-делегат держит ссылку на обработчик; не отписались — не собрали |
| LOH-объекты | > 85 КБ не уплотняются и живут в Gen2 |
| Boxing | каждая упаковка создаёт новый объект в куче → нагрузка на GC |

## Вывод

Утечки в .NET возникают из-за корневых ссылок (статика, события, глобальные
обработчики). Это подтверждено измерениями памяти до/после `GC.Collect()`.
