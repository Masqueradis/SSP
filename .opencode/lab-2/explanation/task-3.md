# Задание 3 — Тестирование и анализ + Memory Profiler (снапшоты кучи)

**Файлы:**
- `Lab2/Task3/Program.cs` — тестирование/анализ `MemoryMonitor`;
- `Lab2/DumpTool/` — создание снимков кучи;
- `Lab2/DumpReader/` — чтение и сравнение снимков.
**Целевая платформа:** .NET 10.0 (SDK 10.0.401)

## Часть 1. Тестирование и анализ (Task3)

Main по скелету из условия: базовое выделение → LOH → boxing → принудительная
сборка → оптимизированная версия (без упаковки).

```
Время с упаковкой (List<object>): 84ms
Время без упаковки (List<int>):    7ms
```

Поколения и счётчики сборок показывают работу GC; после `Cleanup()` +
`GC.Collect()` управляемая память падает до 0 МБ.

## Часть 2. Memory Profiler (DumpTool + DumpReader)

Для анализа кучи программа модифицирована: между первым и вторым снимком
выделяется большой массив (10 МБ) и 50 LOH-объектов — так «в разных местах
работы программы» получается два разных состояния памяти.

### DumpTool — создание снимков

`DiagnosticsClient.WriteDump(DumpType.WithHeap, dumpPath)` создаёт дамп кучи
текущего процесса. Используются DLL: `Microsoft.Diagnostics.NETCore.Client`
(подключена как NuGet-пакет). Снимки лежат в `bin/Debug/net10.0/Dumps/`.

```
heap_dump_stage1_*.dump: 103372.00 KB   (до выделения массива)
heap_dump_stage2_*.dump: 127428.00 KB   (после выделения массива)
```

### DumpReader — чтение и сравнение

- `DataTarget.LoadDump(path)` → `ClrRuntime` → `runtime.Heap`;
- `heap.EnumerateObjects()` даёт `ClrObject` (свойства `Type`, `Size`);
- вывод ТОП-20 типов по занимаемой памяти;
- режим сравнения двух дампов (рост по типам).

Пример сравнения:

```
Живая куча: дамп1 = 2.19 MB, дамп2 = 16.97 MB, разница = +14 MB
System.Byte[]: 1 -> 16 MB   (добавленные массив и LOH-объекты)
Типов появилось: 6, исчезло: 9
=> Рост кучи между снимками указывает на удерживаемые объекты.
```

### Замечание по API

В условии использован `DataTarget.LoadCrashDump` (ClrMD 2.x). В NuGet-версии
Microsoft.Diagnostics.Runtime 3.1 этот метод называется `DataTarget.LoadDump`,
а `heap.TotalHeapSize`/`ClrType.GetSize` заменены свойством `ClrObject.Size`
и перебором объектов. Логика та же.

> Нюанс: эталонные дампы из `damp_heap` (созданы на Windows) ClrMD 3.1 под Linux
> не распознаёт — программа выдаёт понятное сообщение «CLR не обнаружена».
> Демонстрация выполняется на дампах, созданных самим `DumpTool` на текущей машине.

## Вывод

Сравнение снапшотов — стандартный приём профилирования: два снимка в разных
точках программы показывают, какие типы «растут» и удерживаются между снимками
(потенциальные утечки).
