# Задание 6 — Оптимизация через устранение упаковки (Boxing Elimination)

**Файл:** `Lab2/Task6/Program.cs`
**Целевая платформа:** .NET 10.0 (SDK 10.0.401)

## Суть задания

1. Сравнить производительность `List<object>` (с упаковкой) и `List<int>`
   (без упаковки) на 1 000 000 операций; сравнить расход памяти; сформировать
   отчёт-таблицу.
2. Оптимизировать код с `ArrayList` → `List<int>` и объяснить причины ускорения.

## Что такое упаковка

```csharp
int number = 42;            // значимый тип, живёт на стеке
object boxedNumber = number; // упаковка: выделяется объект в куче
int unboxedNumber = (int)boxedNumber; // распаковка (явление преобразование)
```

Упаковка создаёт в управляемой куче новый объект (заголовок + значение),
что нагружает GC и требует очистки. `List<int>` — обобщённая коллекция, хранит
значения без промежуточных объектов.

## Часть 1. Сравнение производительности (1 000 000 операций)

| Вариант | Время, мс | Память (куча), МБ |
|---|---|---|
| С упаковкой (List\<object\>) | 84.6 | 30.9 |
| Без упаковки (List\<int\>) | 5.6 | 4.0 |

**Ускорение: ~15x** (больше ожидаемых 2–4x). Память без упаковки меньше в
~7 раз: не создаются 1 000 000 боксов по ~24 байта.

## Часть 2. Оптимизация ArrayList → List<int>

| Код | Добавление, мс | GetSum, мс |
|---|---|---|
| ArrayList (упаковка при Add и распаковка при foreach) | 99.8 | 9.5 |
| List\<int\> (оптимиз.) | 9.2 | 3.8 |

**Добавление в 10.8x быстрее, GetSum в 2.5x быстрее.**

## Причины ускорения

- `ArrayList` хранит `object`: каждый `Add(i)` — упаковка `int` (объект в
  куче), каждый `foreach (object item)` + `(int)item` — распаковка.
- `List<int>` хранит значения напрямую, обращений к куче нет.
- Побочный эффект: меньше аллокаций → меньше работы GC.

## Замечание о сумме

`GetSum()` возвращает `int`; сумма 1,000,000 значений выходит за границы `int`
и «переполняется» одинаково в обоих вариантах (1783293664), что подтверждает
идентичность логики до и после оптимизации.
