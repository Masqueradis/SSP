# Задание 7 — Поиск утечек в коде (BuggyCode)

**Файл:** `Lab2/Task7/Program.cs`
**Целевая платформа:** .NET 10.0 (SDK 10.0.401)

## Суть задания

Найти и исправить утечки памяти в представленном коде, объяснить причину
каждой и реализовать исправленную версию.

## Исходный код

```csharp
public class BuggyCode
{
    private static List<IDisposable> _cache = new List<IDisposable>();
    private static event EventHandler _globalEvent;
    private byte[] _data = new byte[1024 * 1024];
    public BuggyCode()
    {
        _globalEvent += OnEvent;            // (2)
        _cache.Add(new MemoryStream(1024)); // (1), (3)
    }
    // ...
    public void SubscribeAll()              // (4)
    { for (int i = 0; i < 1000; i++) new BuggyCode(); }
}
```

## Найденные утечки

1. **`static List<IDisposable> _cache`** — коллекция никогда не очищается и
   растёт с каждым созданием объекта; все `MemoryStream` удерживаются до конца
   приложения.
2. **`static event _globalEvent`** — конструктор подписывает `OnEvent()` и
   никогда не отписывается. Делегат держит ссылку на экземпляр → объект нельзя
   собрать, даже удалив ссылки на него.
3. **`new MemoryStream(1024)` без `Dispose()`** — утечка неуправляемых
   (native) ресурсов даже при удалении ссылки из списка, если не вызвать
   `Dispose()`.
4. **`SubscribeAll()`** — создаёт 1000 объектов без ссылок на них, но каждый
   удерживается событием и кэшем (см. п. 1–2).

## Демонстрация утечки (оригинальный код)

```
Создали 400 экземпляров (без сохранения ссылок). Элементов в кэше: 400
Память после создания + GC.Collect(): 100 MB   <- не освободилась
```

## Исправления (FixedBuggyCode)

- `Dispose()` отписывает `_globalEvent -= OnEvent` — разрывает ссылку на
  экземпляр; счётчик живых подписчиков уменьшается.
- `ClearCache()` вызывает `Dispose()` у каждого `MemoryStream`, затем чистит
  список и принудительно собирает мусор.
- `Dispose()` идемпотентен (флаг `_disposed`).

## Результат исправленной версии

```
Память после создания: 200 MB (живых подписчиков: 400)
Память после Dispose всех + ClearCache + GC.Collect: 100 MB
Освобождено: 99 MB, живых подписчиков: 0
```

## Вывод

Все 4 причины утечки связаны с корневыми ссылками: статическое поле,
статическое событие и неосвобождённые `IDisposable`. Исправление — строгая
отписка, освобождение ресурсов и очистка статических коллекций.
