# Testing Guide — Лабораторная работа 2

**Тема:** Управление памятью в C# и анализ утечек (GC, поколения, LOH, boxing)

Пошаговая инструкция по запуску, демонстрации и сдаче преподавателю.

Выполнено на **.NET 10.0** (SDK 10.0.401, установлен в `~/.dotnet`). Все проекты —
в `Lab2/Task1` … `Lab2/Task7` + инструменты анализа `Lab2/DumpTool`,
`Lab2/DumpReader`.

> Примечание: если на машине преподавателя установлен только SDK 8.0, нужно либо
> поставить .NET 10 SDK, либо в каждом `.csproj` поменять `<TargetFramework>`
> на `net8.0` (код совместим).

## 1. Задание 1 — Базовые примеры утечки

**Команда:** `cd Lab2/Task1 && dotnet run`

**Что должно быть на экране (ключевые блоки):**
```
Объект 1: статический список (общий): [100, 200, 300], экземплярный (свой): [1]

Total Memory: 18 MB  (после выделения) → 28 MB (после утечек) → 4 MB (после очистки)
```

после `Cleanup()` падает.

## 4. Анализ дампов — DumpTool + DumpReader (Memory Profiler)

Эти инструменты закрывают пункт задания «Сравните несколько snapshots
в разных местах работы программы» из раздела про Memory Profiler.

**Шаг 1. Создать два снимка кучи**
```bash
cd Lab2/DumpTool && dotnet run
```
Появится папка `Lab2/DumpTool/bin/Debug/net10.0/Dumps/` с двумя дампами
(`heap_dump_stage1_*.dump` ~100 МБ и `heap_dump_stage2_*.dump` ~127 МБ),
второй сделан **после** выделения массива 10 МБ и 50 LOH-объектов.

**Шаг 2. Прочитать один снимок**
```bash
cd Lab2/DumpReader
dotnet run -- "../DumpTool/bin/Debug/net10.0/Dumps/heap_dump_stage1_<...>.dump"
```
Ожидается: `Живая куча`, `Корни GC`, таблица ТОП-20 типов (лидирует
`System.Byte[]`), `Всего типов: ~265`.

**Шаг 3. Сравнить два снимка**
```bash
cd Lab2/DumpReader
dotnet run -- "../DumpTool/bin/Debug/net10.0/Dumps/heap_dump_stage1_<...>.dump" \
            "../DumpTool/bin/Debug/net10.0/Dumps/heap_dump_stage2_<...>.dump"
```
Ожидается:
```
Живая куча: дамп1 = ~2 MB, дамп2 = ~17 MB, разница = +14 MB
System.Byte[]: 1 -> 16 MB      <- добавленные массив и LOH-объекты
```

**Объяснение для преподавателя:** используется библиотека ClrMD;
`DataTarget.LoadDump` (в условии `LoadCrashDump` — старое название API 2.x)
читает дамп, `ClrHeap.EnumerateObjects()` даёт список объектов и их размеры.

## 8. Задание 7 — Поиск утечек в BuggyCode

**Команда:** `cd Lab2/Task7 && dotnet run`

**Ожидаемый результат:**
```
Оригинал: создали 400 экземпляров → память 100 MB, GC.Collect() не освобождает
Исправление: Dispose() всех + ClearCache + GC.Collect → освобождено 99 MB, подписчиков: 0
```

**Объяснение для преподавателя:** в коде 4 утечки — статический кэш, отсутствие
отписки от статического события, MemoryStream без Dispose, «безымянные»
экземпляры. Исправлено через `Dispose()`+отписку+очистку кэша.
> Демонстрация уменьшена до 400×256 КБ (ввиду ограниченных ресурсов машины),
> по условию демонстрация — 1000×1 МБ, заменив константы `Count`/`SizeKB` в строках
> 95–96 `Program.cs`.
