# Руководство по тестированию лабораторной работы №8

**Тема:** Разработка смарт-контрактов на Solidity  
**Среда тестирования:** [Remix IDE](https://remix.ethereum.org)  
**Версия Solidity:** ^0.8.19

## Подготовка к тестированию

### 1. Открытие Remix IDE
1. Перейти по ссылке [https://remix.ethereum.org](https://remix.ethereum.org)
2. Дождаться загрузки среды

### 2. Загрузка контракта
1. В левой панели выбрать вкладку "File Explorer"
2. Нажать "+ Create New File"
3. Создать файл `StudentRegistry.sol`
4. Скопировать содержимое файла `Lab8/StudentRegistry.sol` из репозитория в редактор Remix
5. Нажать `Ctrl+S` или кнопку компиляции для сохранения и компиляции

Альтернативно можно загрузить оба файла: `StudentRegistry.sol` и `ExtendedStudentRegistry.sol`.

## Компиляция контракта

1. Перейти на вкладку "Solidity Compiler" (иконка с логотипом Solidity) в левой панели
2. В поле "Compiler" выбрать версию `0.8.19` (или совместимую с ^0.8.19)
3. Нажать "Compile StudentRegistry.sol"
4. Убедиться, что компиляция прошла успешно (зелёная галочка)

## Деплой контракта

1. Перейти на вкладку "Deploy & Run Transactions" в левой панели
2. В поле "Environment" выбрать `Remix VM (Cancun)` (или любую другую Remix VM)
3. В поле "Account" выбрать аккаунт (по умолчанию первый из списка) - он станет администратором контракта
4. В выпадающем списке "Contract" выбрать `StudentRegistry`
5. В поле "Deploy" рядом с конструктором ввести название университета, например: `"My University"`
6. Нажать "Deploy"
7. Внизу панели появится развернутый контракт под заголовком "Deployed Contracts"

## Тестовые сценарии

### Сценарий 1. Регистрация студентов
**Цель:** Проверить добавление студентов в реестр

1. Развернуть контракт в разделе "Deployed Contracts"
2. Найти функцию `registerStudent`
3. Заполнить поля:
   - `_name` (string): `"John Doe"`
   - `_age` (uint256): `20`
   - `_major` (string): `"Computer Science"`
4. Нажать "transact"
5. Повторить для второго студента:
   - `_name`: `"Jane Smith"`, `_age`: `21`, `_major`: `"Mathematics"`
6. Повторить для третьего студента:
   - `_name`: `"Alex Johnson"`, `_age`: `19`, `_major`: `"Physics"`

**Ожидаемый результат:** Транзакции успешно выполнены. События `StudentRegistered` отображаются в логах.

### Сценарий 2. Просмотр информации о студентах
**Цель:** Проверить функции чтения данных

1. Вызвать функцию `getStudentCount()` - нажать "call"
   - **Ожидаемый результат:** `3` (или количество зарегистрированных студентов)
2. Вызвать `getStudent(1)` - нажать "call"
   - **Ожидаемый результат:** Возвращает кортеж `(John Doe, 20, Computer Science, true)`
3. Вызвать `getStudent(2)` - нажать "call"
   - **Ожидаемый результат:** Данные второго студента
4. Вызвать `getAllStudents()` - нажать "call"
   - **Ожидаемый результат:** Возвращает 4 массива с данными всех активных студентов (ids, names, ages, majors)

### Сценарий 3. Поиск студента по адресу
**Цель:** Проверить привязку студента к адресу администратора

1. Скопировать адрес аккаунта из выпадающего списка "Account" (адрес, с которого производилась регистрация)
2. Найти функцию `getStudentByAddress`
3. В поле `_address` вставить скопированный адрес
4. Нажать "call"
   - **Ожидаемый результат:** Возвращает информацию о студенте, привязанном к этому адресу (по умолчанию привязывается последний зарегистрированный или тот, что был зарегистрирован при вызове с этого адреса)

Примечание: В текущей реализации `studentIdByAddress[msg.sender]` перезаписывается при каждой регистрации с одного адреса.

### Сценарий 4. Обновление данных студента
**Цель:** Проверить функцию обновления

1. Вызвать функцию `updateStudent`
2. Заполнить поля:
   - `_studentId`: `1`
   - `_newName`: `"John Doe Jr."`
   - `_newAge`: `21`
   - `_newMajor`: `"Software Engineering"`
3. Нажать "transact"
4. Вызвать `getStudent(1)` для проверки
   - **Ожидаемый результат:** Данные студента с ID 1 обновлены. Событие `StudentUpdated` в логах

### Сценарий 5. Удаление студента
**Цель:** Проверить мягкое удаление (пометка неактивным)

1. Вызвать функцию `deleteStudent`
2. Поле `_studentId`: `2`
3. Нажать "transact"
4. Вызвать `getStudentCount()` 
   - **Ожидаемый результат:** Счетчик уменьшился (студент ID 2 больше не учитывается)
5. Вызвать `getAllStudents()`
   - **Ожидаемый результат:** В списке отсутствует студент с ID 2
6. Попробовать вызвать `getStudent(2)`
   - **Ожидаемый результат:** Ошибка "Student does not exist" (так как модификатор `studentExists` проверяет `isActive`)

### Сценарий 6. Проверка прав доступа
**Цель:** Проверить работу модификатора `onlyAdmin`

1. В выпадающем списке "Account" выбрать другой аккаунт (не администратор)
2. Попробовать вызвать `registerStudent` с любыми данными и нажать "transact"
   - **Ожидаемый результат:** Транзакция отклонена с ошибкой "Only admin can call this"
3. Вернуть аккаунт администратора для продолжения тестирования

### Сценарий 7. Тестирование наследования (ExtendedStudentRegistry)
**Цель:** Демонстрация работы наследования

1. В выпадающем списке "Contract" выбрать `ExtendedStudentRegistry`
2. В поле деплоя конструктора ввести:
   - `_universityName`: `"My University"`
   - `_department`: `"Faculty of Computer Science"`
3. Нажать "Deploy"
4. Используя аккаунт администратора, вызвать `registerStudent` для регистрации студента в новом контракте
5. Вызвать `getStudentWithMajor(1, "Computer Science")` - нажать "call"
   - **Ожидаемый результат:** `true`, если специальность совпадает
6. Вызвать `getStudentWithMajor(1, "Mathematics")` - нажать "call"
   - **Ожидаемый результат:** `false`
7. Вызвать `setDepartment("Faculty of Engineering")` и проверить через чтение публичного поля `department`
   - **Ожидаемый результат:** Название кафедры обновлено

## Дополнительные проверки

- **Проверка валидации:** Попробовать зарегистрировать студента с пустым именем, возрастом 0 или 200 - должно выдаваться соответствующее сообщение об ошибке
- **События:** Во вкладке "Transaction Receipt" или в логах можно увидеть сгенерированные события
- **Публичные поля:** Можно напрямую прочитать `admin`, `universityName`, `studentCount`, `students[]`, `studentIdByAddress[]`

## Возможные проблемы и решения

| Проблема | Решение |
|----------|---------|
| Ошибка компиляции | Проверить версию компилятора (должна быть 0.8.19) |
| "Only admin can call this" | Убедиться, что используется аккаунт, с которого был задеплоен контракт |
| "Student does not exist" | Студент либо не зарегистрирован, либо был удалён (isActive = false) |
| "Student not found" | При поиске по адресу студент не привязан к этому адресу |
