## Созданные файлы

### `Lab8/StudentRegistry.sol`
Основной смарт-контракт, содержащий:
- **Структура `Student`** - хранение данных о студенте (имя, возраст, специальность, статус активности)
- **Состояния контракта** - `admin`, `universityName`, `studentCount`
- **Маппинги** - `students[studentId]`, `studentIdByAddress[address]`
- **События** - `StudentRegistered`, `StudentUpdated`, `StudentDeleted`
- **Модификаторы** - `onlyAdmin`, `studentExists`
- **Конструктор** - инициализация контракта с названием университета
- **Основные функции**:
  - `registerStudent()` - регистрация студента (только админ)
  - `updateStudent()` - обновление данных студента (только админ)
  - `deleteStudent()` - удаление студента (пометка как неактивный, только админ)
- **Функции чтения**:
  - `getStudent()` - получение информации о студенте по ID
  - `getStudentByAddress()` - получение информации о студенте по адресу
  - `getAllStudents()` - получение всех активных студентов
  - `getStudentCount()` - подсчет активных студентов
  - `isStudentRegistered()` - проверка регистрации студента
- **Функции администрирования**:
  - `changeAdmin()` - смена администратора
  - `setUniversityName()` - смена названия университета

В том же файле реализован контракт **`ExtendedStudentRegistry`** (наследование от `StudentRegistry`):
- Поле `department` - кафедра
- `setDepartment()` - установка кафедры
- `getStudentWithMajor()` - проверка соответствия специальности студента заданной

### `Lab8/ExtendedStudentRegistry.sol`
Дополнительный файл с контрактом `ExtendedStudentRegistry` (для удобства).

## Ключевые концепции Solidity, использованные в работе

- **Structs** - пользовательские типы данных для группировки связанных полей
- **Mappings** - хеш-таблицы для хранения пар "ключ-значение"
- **Arrays** - динамические массивы для возврата списков данных
- **Modifiers** - переиспользуемые проверки условий
- **Events** - логирование событий для отслеживания действий
- **View/Pure функции** - функции только для чтения, не изменяющие состояние блокчейна
- **Constructor** - инициализация контракта при деплое
- **Inheritance** - наследование функционала одного контракта другим
- **Error handling** - обработка ошибок с помощью `require()`
- **msg.sender** - адрес вызывающего функцию
- **indexed** - индексация параметров событий для удобного поиска

## Особенности реализации

- Все функции модификации данных доступны только администратору (`onlyAdmin`)
- При удалении студент помечается как неактивный (`isActive = false`), данные остаются в блокчейне
- `getAllStudents()` возвращает только активных студентов
- При регистрации студента автоматически привязывается адрес вызывающего (`msg.sender`)
- Используется валидация входных данных через `require()`
- Контракты соответствуют синтаксису Solidity ^0.8.19
