# Задание 3 — Task и async/await

**Проект:** `Lab5/Task3` · **Запуск:** `cd Lab5/Task3 && dotnet run`
**Источник:** `МногопотАинхПрогр.docx`, задание 3

## Что делает программа

Разбирает асинхронность на конкретных примерах: разница `Thread.Sleep` и
`Task.Delay`, параллельные «загрузки», периодический таймер, ввод/вывод,
`Task.Run` и обработку исключений.

### Часть 3.1. Thread.Sleep против Task.Delay

Метод имитирует загрузку файла на 500 мс и печатает, сколько времени
поток был занят (`GetProcessTimes` через P/Invoke `libc`). Синхронный вариант
с `Thread.Sleep` занимает поток все 500 мс; вариант с `await Task.Delay`
переводит поток в состояние ожидания и освобождает его сразу.

Вывод: `Task.Delay` не держит поток — пока задача ждёт, поток обслуживает
другие задачи.

### Часть 3.2. Task.WhenAll на трёх «загрузках»

Три задачи с задержками 1500/1200/900 мс запускаются одновременно.

```
Загрузка site-1 начата (поток 7), задержка 1500 мс
Загрузка site-3 начата (поток 9), задержка 1200 мс
Загрузка site-2 начата (поток 8), задержка 900 мс
...
Суммарное время: 1502 мс (сумма задержек = 3600 мс)
```

3600 мс превратились в 1502 мс — время определяется самой долгой задачей.
Программа печатает реальные идентификаторы потоков: это **разные** потоки пула,
то есть `await` действительно освободил потоки.

### Часть 3.3. Асинхронный таймер

`PeriodicTimer` тикает 5 раз с периодом 2 секунды (10 секунд), время
фиксируется по `Stopwatch` и печатается с миллисекундами.

```
[2.0 с] Тик 1 · [4.0 с] Тик 2 · [6.0 с] Тик 3 · [8.0 с] Тик 4 · [10.0 с] Тик 5
```

Отклонения от ровных 2 секунды — единицы миллисекунд, то есть таймер
реально работает асинхронно, без `Thread.Sleep` в цикле.

### Часть 3.4. BigInteger и Task.Run

`Fib(2000)` считается синхронно и через `Task.Run`. В обоих случаях — 418 цифр,
результаты совпадают.

Вывод, который печатает программа: `Task.Run` лишь выносит вычисление в поток
пула, оно остаётся **синхронным и блокирующим**. Для настоящей асинхронности
CPU-задачу надо разбивать и отдавать через `await`.

### Часть 3.5. Исключения в асинхронном коде

Три сценария: успех, `try/catch/finally` с `await`, `await` без `try` (исключение
попадает в `Task` и всплывает при `await`). Показывается, что `try/finally` без
`await` не защищает от асинхронных исключений.

## Ключевые выводы

1. `async/await` освобождает поток на время ожидания; `Thread.Sleep` — нет.
2. `Task.WhenAll` даёт суммарное время, равное самой долгой задаче.
3. `Task.Run` не делает код асинхронным, он только меняет поток.
4. `try/catch` работает с `await`, но не работает с задачей, запущенной без
   ожидания внутри блока.
5. Для I/O-bound работы `async/await` даёт выигрыш без единого потока CPU.
