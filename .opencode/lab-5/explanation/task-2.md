# Задание 2 — Пул потоков (ThreadPool)

**Проект:** `Lab5/Task2` · **Запуск:** `cd Lab5/Task2 && dotnet run`
**Источник:** `МногопотАинхПрогр.docx`, задание 2

## Что делает программа

Сравнивает создание потоков вручную с постановкой задач в пул на трёх уровнях:
параметры пула, единичная задача и массовая нагрузка.

### Часть 2.1. Параметры ThreadPool

Печатаются `GetMinThreads`, `GetMaxThreads`, `GetAvailableThreads` для рабочих
потоков и потоков ввода-вывода, а также `Environment.ProcessorCount`.

На машине с 8 ядрами: минимум 8 рабочих потоков, максимум — 32767 (это не 8,
а предел, до которого пул может дорасти при большой нагрузке), для ввода-вывода
отдельный лимит 1000.

### Часть 2.2. Двадцать задач

20 задач имитируют операцию на 500 мс. Главный поток сразу продолжает работу,
показывает, что постановка задачи **не блокирует**. Затем `Task.WaitAll` дожидается
всех.

В выводе видно, что 20 задач выполняются всего на 4–5 потоках одновременно
(по умолчанию пул наращивается медленно, по одному потоку каждые 500 мс) — это
значимое отличие от `Thread`, где каждый `Task` получил бы свой поток.

### Часть 2.3. 1000 потоков против 1000 задач

| Способ | Результат |
|--------|-----------|
| 1000 × `new Thread(...)` | создаётся 1000 настоящих потоков ОС, каждая со своим стеком |
| 1000 × `Task.Run(...)` | используется ограниченное число потоков пула |

Программа печатает реальные идентификаторы потоков (`gettid` через P/Invoke) и
считает, сколько **уникальных** потоков фактически участвовало. Разница
показывает главное свойство пула: количество потоков не равно количеству задач.

### Часть 2.4. Переиспользование потоков

Отдельная серия из 500 задач, работающих по 10 мс, собирает идентификаторы
потоков в `ConcurrentDictionary`. Оказывается, что задачи выполняются теми же
самыми потоками по кругу — доказательство переиспользования вместо создания
нового потока на каждую задачу.

## Ключевые выводы

1. `ThreadPool` экономит память: не нужен свой стек на задачу.
2. Пул растёт плавно, поэтому для коротких задач сначала выполняется лишь несколько.
3. Переиспользование потоков убирает накладные расходы на создание.
4. Если задаче нужен выделенный поток или приоритет — только `Thread`;
   иначе всегда `ThreadPool`.
5. `Task.Factory.StartNew` для CPU-задач лучше не использовать: он запускает задачу
   на потоке пула **синхронно**, и `await Task.Run` надёжнее.
