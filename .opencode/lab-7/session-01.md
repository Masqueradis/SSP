# Сессия 01 — Лабораторная работа 7 «IoT-симулятор датчика с передачей данных в облачный сервер»

## 1. Поставленные задачи

Реализовать лабораторную работу 7 по методическим указаниям
`.opencode/lab-7/Лаб_7IoT20Jul.docx` (текст извлечён из docx разбором
`word/document.xml`):

1. **Задание 1** — сохранять строку состояния температуры и влажности в
   текстовый файл (её затем отправляем в облако);
2. **Задание 2** — базовый MQTT-клиент (MQTTnet, DLL из папки `libs`),
   подключение к публичному брокеру, подписка на `test/topic`, Эксперимент 1
   (обмен сообщениями);
3. **Задание 3** — интеграция симулятора датчика с MQTT (JSON-телеметрия в
   облако), плюс финальное **ЗАДАНИЕ**: гудок при T < 22 °C, вывод данных в
   файл на диске, параметр «освещение» в модели среды;
4. 10 контрольных вопросов, отчёт, руководство по проверке.

Особые условия от пользователя: демонстрация будет идти **на macOS**, поэтому
WinForms-пример из методички заменён на кроссплатформенный **Avalonia UI**
(окно с графиком); структура `Task1–Task3`, документация
`session + testing-guide + answers`.

## 2. Подготовка

- Создана структура `Lab7/Task1`, `Lab7/Task2/libs`, `Lab7/Task3/libs`,
  `Lab7/Listener/libs`;
- Скачан с NuGet `mqttnet.3.1.2.nupkg` (версия API 3.x, как в методичке:
  `MqttClientConnectedHandlerDelegate`, свойство `Payload` как `byte[]`),
  из `lib/netstandard2.0/MQTTnet.dll` скопирован в `libs/` трёх проектов;
- Проверена сеть: `broker.hivemq.com:1883` и `test.mosquitto.org:1883`
  отвечают (`/dev/tcp`-тест), nuget.org доступен;
- Выбрана Avalonia **11.3.22** (последняя стабильная 11-я ветка во всех
  нужных пакетах: `Avalonia`, `.Desktop`, `.Themes.Fluent`, `.Fonts.Inter`).

## 3. Выполненная работа

### Task1 — Задание 1, окно датчика (Avalonia)

- `Task1.csproj` — net10.0, пакеты Avalonia 11.3.22;
- `Program.cs`, `App.axaml(.cs)` — стандартный каркас Avalonia desktop;
- `Sensor.cs` — `EnvironmentAwareSensor` и `SensorData` из теоретической
  части методички (шум ±3 °C, влияние двери/AC/обогревателя/людей,
  корреляция влажности с температурой);
- `ChartControl.cs` — порт `GraphForm_Paint` из методички: бело-серый фон
  графика, сетка и подписи осей (5 делений Y, время на X), красная линия с
  точками и подписями значений. **Правка после первой сборки:** в Avalonia
  рисование переопределяется через `public override void Render(DrawingContext)`
  (метода `OnRender` там нет — ошибка CS0115 устранена);
- `MainWindow.axaml(.cs)` — информационная панель (красная строка
  температуры/влажности + синий статус), кнопки «Добавить показание» /
  «Очистить», таймер 2 с, стартовые 5 показаний, автосценарий воздействий
  (8/12/15/12/10 с) через `Dispatcher.UIThread.InvokeAsync`;
  **Задание 1**: каждая строка состояния дописывается в `readings.txt`
  (`File.AppendAllText` под локом), после первой записи в консоль выводится
  `=== ЗАДАНИЕ 1 ВЫПОЛНЕНО ===`;
- после CS0115 ошибка вида WinForms-`OnFormClosed` была заменена на
  Avalonia-`OnClosed`.

### Task2 — Задание 2, базовый MQTT-клиент

- `.csproj` строго по образцу методички: `<Reference Include="MQTTnet">` +
  `HintPath libs/MQTTnet.dll` + копирование DLL в выходную папку
  (использован прямой слэш — на Windows/msbuild тоже работает);
- `Program.cs` по шаблону методички: подключение к `broker.hivemq.com:1883`,
  обработчики `Connected`/`Disconnected`/`ApplicationMessageReceived`,
  подписка на `test/topic` (QoS 1), автоотправка 5 сообщений с интервалом
  0.7 с, ожидание эха до 10 с, затем в интерактивном режиме — ручная
  отправка строк, в неинтерактивном — автовыход;
- **правка после сборки:** `MqttClientPublishReasonCode` живёт в неймспейсе
  `MQTTnet.Client.Publishing` — добавлен `using`.

### Task3 — Задание 3 + финальное ЗАДАНИЕ

- Конвейер методички сохранён: `EnvironmentAwareSensor` (инерционная модель с
  `deltaMinutes`, дверь/обогреватель/кондиционер/люди, суточный цикл, шум,
  `Math.Clamp`) → JSON (`System.Text.Json`, camelCase) → публикация QoS 1 в
  `iot/devices/simulated/data` на `test.mosquitto.org:1883`, команда-цикл
  консоли (`door/heater/ac/add/remove/status/exit`), статистика каждые 30 с,
  `ReconnectMqttClient()`, ASCII-график `DrawTemperatureChart`;
- **Гудок < 22 °C:** `BeepAlarm()` вызывается на переходе
  `21.99 < 22` (флаг `_wasBelow22`, без спама), пишет красную строку,
  шлёт `\a` + `Console.Beep()` в try/catch, считает `_beepCount`; в строке
  статуса горит `🚨 T < 22 °C!`;
- **Файл на диске:** `AppendDataFile()` дописывает JSON-строку в
  `telemetry.txt` (путь печатается при старте), счётчик строк в итогах;
- **Освещение:** поле `_isLightOn` + команда `light on/off`; суточный цикл
  дневного света `50 + 950·max(0, sin(π·(час−6)/12))` лк от **локального**
  времени, лампа даёт +350 лк (ночь: 50 → 400 лк) и нагрев +0.15 °C/мин;
  `isLightOn`/`illumination` — в metadata, телеметрии, `status` и строке
  вывода;
- Неинтерактивный запуск: при закрытом stdin работает 20 с (или `N` аргументом
  `dotnet run -- N`) и завершается с `=== ЗАДАНИЕ 3 ВЫПОЛНЕНО ===`; ввод
  `null` из `ProcessCommands` больше не крутит цикл вхолостую, `exit` ведёт
  к корректному отключению.

### Listener — утилита проверки доставки в облако

- Отдельный консольный проект с тем же `libs/MQTTnet.dll`: подписывается на
  `iot/devices/simulated/data` (или топик из аргументов), печатает каждое
  сообщение в разобранном виде (JSON → поля + metadata), считает и в конце
  выдаёт `=== ДОСТАВКА В ОБЛАКО ПОДТВЕРЖДЕНА ===` или предупреждение;
  неинтерактивный режим слушает 40 с.

## 5. Ключевые выводы

1. MQTTnet 3.1.2 (netstandard2.0) спокойно работает на net10.0 — API методички
   не потребовал адаптации, кроме неймспейса `MqttClientPublishReasonCode`;
2. WinForms нигде, кроме Windows, не работает — замена на Avalonia UI
   сохранила и окно, и график, и кнопки, и привычный консольный лог;
3. Сквозной цикл IoT подтверждён: симулятор → `test.mosquitto.org` →
   независимый `Listener` принял 12 сообщений с корректным JSON
   (включая `isLightOn`/`illumination`);
4. Порог гудка отрабатывает на реальном пересечении 22 °C (шум модели даёт
   1–3 срабатывания за 25–65 с, команды `ac on`/`door open` уводят температуру
   вниз детерминированно);
5. Файловый след (`readings.txt`, `telemetry.txt`) — выполнение Задания 1 и
   пункта «выводите данные в файл» финального задания.
