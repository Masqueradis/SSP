# Testing Guide — Лабораторная работа 7

**Условие:** методические указания `Лаб_7IoT20Jul.docx` — «Разработка
IoT-симулятора датчика с передачей данных в облачный сервер».

**Темы:** моделирование датчика (инерционность, суточные циклы, шум,
корреляция), MQTT (брокер/издатель/подписчик/топик, QoS, Keep Alive),
публикация JSON-телеметрии в облако, реагирование на порог температуры.

Пошаговая инструкция: что запустить, что должно быть выведено на экран и как
продемонстрировать работоспособность преподавателю.

Проверено на **.NET 10** (`dotnet --version` → 10.0.112), Linux, публичные
брокеры `broker.hivemq.com` и `test.mosquitto.org` (порт 1883) доступны из
сети. Проекты — в `Lab7/Task1`, `Lab7/Task2`, `Lab7/Task3`, `Lab7/Listener`.
Для демонстрации годится **macOS** (всё кроссплатформенно).

**Соответствие нумерации** (в документе — «Задание N», в проекте — `TaskN`):

| Задание из `Лаб_7IoT20Jul.docx`              | Проект                        |
|----------------------------------------------|-------------------------------|
| Задание 1 — строка состояния в текстовый файл | `Lab7/Task1` (окно Avalonia) |
| Задание 2 — базовый MQTT-клиент, Эксперимент 1 | `Lab7/Task2`                |
| Задание 3 — интеграция датчика с MQTT         | `Lab7/Task3`                  |
| + финальное ЗАДАНИЕ (гудок <22 °C, файл, освещение) | `Lab7/Task3`           |
| (проверка доставки в облако — утилита)        | `Lab7/Listener`               |

> `Task1` — единственное оконное приложение: в методичке пример на WinForms,
> он не работает ни на Linux, ни на macOS, поэтому **графический интерфейс
> перенесён на Avalonia UI 11.3** (кроссплатформенный). Остальные проекты
> консольные.

## 0. Проверка окружения

```bash
dotnet --version          # ожидается 10.x
```

Внешних утилит **не нужно**: MQTTnet.dll лежит в `libs/` каждого проекта
(скачана с NuGet, версия 3.1.2 — как в методичке), Avalonia восстанавливается
из NuGet автоматически.

**На mac (если SDK не установлен):** `brew install --cask dotnet-sdk`
или https://dot.net — затем `dotnet --version`.

Полная проверка сборки всех проектов одной командой:

```bash
cd /home/masqueradis/ssp/Lab7
for p in Task1 Task2 Task3 Listener; do
  dotnet build -v q --nologo $p/$p.csproj 2>&1 | \
    grep -E "error|Error\(s\)|Warning\(s\)" | sed "s/^/$p: /"
done
```

Ожидается для каждого: `0 Error(s)`, `0 Warning(s)`.

## 1. Задание 1 (`Task1`) — окно датчика и файл показаний (~40 с)

```bash
cd Lab7/Task1 && dotnet run
```

Что происходит (окно «IoT Датчик температуры - График», 700×500):

1. Сверху — красная строка `Температура: xx.x°C | Влажность: xx%` и синий
   статус (`Дверь/Кондиционер/Обогреватель/Людей`), кнопки
   **«Добавить показание»** и **«Очистить»**;
2. Ниже — график: точки каждые 2 с, подписи времени и значений по осям;
   кнопка «Добавить показание» добавляет точку вручную, «Очистить» обнуляет
   график (и счётчик строк);
3. В терминале дублируется IoT-лог:
   ```
   📊 [01:20:14] Температура: 21.3°C, Влажность: 60.7%
      Статус: Дверь: закрыта | Кондиционер: выкл | Обогреватель: выкл | Людей: 0
   ------------------------------------------------------------
   ```
4. **Автосценарий внешних воздействий** (как в методичке): через 8 с дверь
   открыта → +12 с включён кондиционер и дверь закрыта → +15 с обогреватель →
   +12 с пришло 3 человека → +10 с обогреватель выключен. Строки событий
   дописываются в статус и в консоль (`🔔 Событие: ...`), график реагирует;
5. **Задание 1**: каждая строка состояния дописывается в текстовый файл
   `bin/Debug/net10.0/readings.txt`:
   ```
   [2026-10-19 01:20:14] Температура: 21.28°C, Влажность: 60.7%, Дверь: закрыта, Кондиционер: выкл, Обогреватель: выкл, Людей: 0
   ```
   При первой записи в консоль выводится:
   ```
   💾 Строки состояния пишутся в файл: .../readings.txt
   === ЗАДАНИЕ 1 ВЫПОЛНЕНО ===
   ```

**Что показывать преподавателю:** живое окно с бегущим графиком и
статусами, файл `readings.txt`, строки в терминале.

## 2. Задание 2 (`Task2`) — базовый MQTT-клиент (~15 с)

```bash
cd Lab7/Task2 && dotnet run
```

Ожидаемый вывод (Эксперимент 1):

```
🌡️ MQTT Client Test (v3.x)
✅ DLL найдена: .../MQTTnet.dll
✅ Клиент создан
✅ Подключено!
🔗 Соединение установлено
📬 Подписались на test/topic (QoS 1)

📤 Отправка 5 сообщений...
📤 Отправлено: Сообщение #1 ...
📩 [1] Получено: Сообщение #1 от TestClient, время 01:29:53
...
📈 Итого: отправлено 5, получено 5

=== ЭКСПЕРИМЕНТ 1 ВЫПОЛНЕН: сообщения отправлены и получены ===
```

Клиент **сам себе и подписчик**: пять сообщений уходят на
`broker.hivemq.com` и возвращаются в то же окно — виден полный цикл
«издатель → брокер → подписчик».

**Интерактивный режим** (запуск без перенаправления ввода): после авто-отправки
печатается `💬 Режим Эксперимента 1` — вводите строки, Enter отправляет их в
`test/topic`, пустая строка — выход. Так можно отправить сообщения вручную.

Проверить чужим клиентом (на mac можно через MQTT Explorer / MQTTX,
подключиться к `broker.hivemq.com`, топик `test/topic`) — придёт и наш поток.

## 3. Задание 3 (`Task3`) — симулятор → облако + финальное ЗАДАНИЕ (~40 с)

```bash
cd Lab7/Task3 && dotnet run
```

Стартует с баннером команд, подключается к `test.mosquitto.org` и каждые 2 с:

```
✅ Подключено к MQTT брокеру: test.mosquitto.org
💾 Данные пишутся в файл: .../telemetry.txt
📊 [01:42:01] [░░░░░░░░░░░░░░░░░░░░░░░░░█░░░░░░░░░░░░░░░] 21.99°C
   💧 60.0% | 💡 свет выкл | ☀️ 50 лк | 👥 0 чел. | 🚪 открыта | 🔥 выкл | ❄️ выкл | 🚨 T < 22 °C!
📈 Статистика за 30 сек: отправлено 16 сообщений, ошибок: 0, циклов: 15, гудков: 1
```

### Три пункта финального ЗАДАНИЯ

1. **Гудок при падении ниже 22 °C.** Команды `ac` → `on` (или `door` → `open`)
   остужают помещение; в момент пересечения порога:
   ```
   🔔 ГУДОК — температура упала ниже 22 °C (21.99 °C)! Требуется внимание!
   ```
   Срабатывает **один раз на каждый переход** через 22 °C, дальше в строке
   статуса горит `🚨 T < 22 °C!`. В терминале посылается символ звонка BEL
   (`\a`) + `Console.Beep()` — на mac в Terminal включён «Audible bell»
   (настройки терминала), будет слышен звук.
2. **Данные пишутся в файл** `bin/Debug/net10.0/telemetry.txt` — построчный
   JSON:
   ```json
   {"deviceId":"simulated_device_001","temperature":21.99,"humidity":60,"timestamp":"2026-10-18T22:42:01.540Z","metadata":{"isDoorOpen":true,"isHeaterOn":false,"isAirConditionerOn":false,"isLightOn":true,"peopleCount":0,"illumination":400,"deltaMinutes":0.04}}
   ```
   В конце работы печатается `💾 Всего записано строк в файл: N`.
3. **Освещение** — новая команда `light` (`on`/`off`):
   ```
   💡 Свет ВКЛЮЧЕН
   ```
   В статусе появляется `💡 свет вкл` и `☀️ 400 лк` (ночью с выключенным
   светом ≈50 лк, днём до 1000 лк от солнца, лампа даёт +350 лк), поле
   `isLightOn` и `illumination` попадают в JSON-телеметрию; свет немного
   нагревает помещение (+0.15 °C/мин) — видно в долгом прогоне.

### Команды (ввод в терминале)

| Команда | Действие |
|---------|----------|
| `door` → `open`/`close` | дверь открыта/закрыта |
| `heater` → `on`/`off` | обогреватель |
| `ac` → `on`/`off` | кондиционер (**лучший способ уронить T ниже 22**) |
| `light` → `on`/`off` | освещение |
| `add` / `remove` | +/- человек |
| `status` | текущее состояние (вкл. освещённости в лк) |
| `exit` | корректный выход с итогами |

Каждые 30 с — строка статистики; в конце — счётчики строк файла и гудков и:

```
=== ЗАДАНИЕ 3 ВЫПОЛНЕНО ===
```

## 4. Проверка доставки в облако (`Listener`, два терминала)

Главное доказательство, что данные ушли на сервер, — **независимый подписчик**:

```bash
# терминал 1
cd Lab7/Task3 && dotnet run

# терминал 2 (через несколько секунд)
cd Lab7/Listener && dotnet run
```

`Listener` печатает каждое принятое сообщение с полями:

```
📥 Сообщение #1 [01:41:59.543]
   deviceId = simulated_device_001
   temperature = 22
   metadata:
     isLightOn = True
     illumination = 400
     ...
================================================
Получено сообщений: 12
=== ДОСТАВКА В ОБЛАКО ПОДТВЕРЖДЕНА ===
```

Альтернативы: MQTT Explorer / MQTTX / веб-клиент HiveMQ
(`https://www.hivemq.com/mqtt/web-client/`, брокер `broker.hivemq.com`) или
`mosquitto_sub -h test.mosquitto.org -t "iot/devices/simulated/data"`.

## 5. Полный прогон (для отчёта)

```bash
cd /home/masqueradis/ssp/Lab7
mkdir -p /tmp/lab7-check

# сборка
for p in Task1 Task2 Task3 Listener; do
  dotnet build -v q --nologo $p/$p.csproj > /tmp/lab7-check/$p.build.log 2>&1
  echo "$p build=$?"
done

# Task2: Эксперимент 1
(cd Task2 && timeout 60 dotnet run --no-build < /dev/null > /tmp/lab7-check/Task2.run.log 2>&1)
echo "Task2 run=$?"

# Task3: подписчик в фоне + симулятор 25 с (дверь и свет для гудка)
(cd Listener && dotnet run --no-build < /dev/null > /tmp/lab7-check/Listener.run.log 2>&1 &)

(cd Task3 && printf 'door\nopen\nlight\non\n' | timeout 60 dotnet run --no-build -- 25 > /tmp/lab7-check/Task3.run.log 2>&1)
echo "Task3 run=$?"
sleep 40

grep -E "ЭКСПЕРИМЕНТ|ВЫПОЛНЕНО" /tmp/lab7-check/*.log
grep "ДОСТАВКА" /tmp/lab7-check/Listener.run.log
```

Ожидается: все `build=0`, `run=0`, в логах есть
`ЭКСПЕРИМЕНТ 1 ВЫПОЛНЕН`, `ЗАДАНИЕ 3 ВЫПОЛНЕНО`, `ДОСТАВКА В ОБЛАКО ПОДТВЕРЖДЕНА`.

`Task1` в этом скрипте не запускается (GUI): он запускается только в окне.

## 6. Частые проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| `dotnet: command not found` | не установлен .NET SDK 10 (mac: `brew install --cask dotnet-sdk`) |
| `Ошибка подключения к MQTT: ...` | нет интернета/закрыт порт 1883; программа продолжает в автономном режиме — проверьте сеть |
| `Сообщений не получено` в Listener | симулятор ещё не запущен / топик не тот; запустите `Task3` первым, топик по умолчанию `iot/devices/simulated/data` |
| Нет звука гудка | `\a` посылается всегда; для звука включите звук терминала (macOS Terminal → Settings → Profiles → Advanced → «Audible bell») |
| Окно `Task1` не открывается | нет графической сессии; в терминале должны быть `DISPLAY`/Wayland |
| Файл `telemetry.txt`/`readings.txt` пуст | смотрите путь из вывода программы — он в `bin/Debug/net10.0/`, а не в корне проекта |
| Хочется чистый файл перед сдачей | удалите `bin/` (`dotnet clean`) и запустите заново |
