# Задание 13 — Parallel.ForEach с коллекциями

**Проект:** `Lab6/Task13` · **Запуск:** `cd Lab6/Task13 && dotnet run`
**Источник:** `ЛабПарПрограм.docx`, задание 2 «Parallel.ForEach с коллекциями»

## Что делает программа

Работа с коллекциями: фильтрация, корректная работа с `ParallelLoopState`
(`Break` и `Stop`), отмена, локальная агрегация и честное сравнение
производительности.

### Часть 13.1. Parallel.ForEach и его аналоги

Программа показывает, что `Parallel.ForEach(list, body)` идёт по коллекции,
а `Parallel.For(0, list.Count, body)` — по диапазону индексов, и что для
списка предпочтителен `ForEach`, поскольку не нужно обращаться по индексу.
Также показана лямбда с двумя аргументами: `Parallel.ForEach(list, (item, index, state) => ...)`.

### Часть 13.2. Break и Stop — разница

Это самая частая ошибка, поэтому здесь она разобрана отдельно:

| | `Break()` | `Stop()` |
|---|---|---|
| Что делает | Просит **этот** поток прекратить итерации | Просит **все** потоки прекратить итерации |
| Итерации других потоков | продолжаются | тоже прекращаются |
| Что попадёт в результат | может быть **больше** порога | может быть **меньше** порога |
| Гарантия | никакой: `ForEach` не упорядочен, проверка `index >= limit` может не сработать | никакой: тело уже начатой итерации успеет доработать |

Программа запускает цикл с `Break()` и с `Stop()` и печатает фактическое
количество обработанных элементов, показывая разницу с ожидаемым порогом.

### Часть 13.3. Отмена через ParallelOptions

Долгий цикл запускается с `new CancellationTokenSource(500)`, переданным
в `ParallelOptions`. Цикл прерывается, а `OperationCanceledException`
перехватывается — это штатный сценарий, не ошибка.

### Часть 13.4. Локальная агрегация

Перегрузка с `localInit` / `localFinally` считает сумму и количество
для каждого потока, а затем сводит. Блококировок в теле цикла нет.

### Часть 13.5. Сравнение производительности

Один и тот же сценарий (суммирование с фильтром) выполняется последовательно
и параллельно, выводятся времена и ускорение (в последнем прогоне — 3.69x).
Вывод печатается явно: **на дешёвой операции выигрыш может исчезнуть,
и это нормально** — параллелизм оправдан для тяжёлой работы на элемент.

## Ключевые выводы

1. `Parallel.ForEach` — для коллекций, `Parallel.For` — для диапазонов индексов.
2. `Break` останавливает только текущий поток, `Stop` — все; **ни один**
   из них не гарантирует, что цикл обработает ровно заданное число элементов.
3. Отмена (`ParallelOptions.CancellationToken`) прерывает цикл корректно.
4. Локальная агрегация (`localInit` / `localFinally`) убирает блокировки из тела.
5. Всегда сравнивайте с последовательным вариантом и печатайте фактическое
   ускорение, а не предполагаемое.
