# Testing Guide — Лабораторная работа 6

**Условие:** методические указания `ЛабПарПрограм.docx` — «Параллельное
программирование в C# с использованием TPL, PLINQ».

**Темы:** `Parallel.For` / `Parallel.ForEach`, `Break()` и `Stop()`, PLINQ,
стратегии разделения данных и агрегация результатов, индивидуальные варианты.

Пошаговая инструкция: что запустить, что должно быть выведено на экран и как
продемонстрировать работоспособность преподавателю.

Проверено на **.NET 10** (`dotnet --version` → 10.0.112), Linux x64, 8 логических ядер.
Все проекты — в `Lab6/Task12` … `Lab6/Task16`, каждое задание — самостоятельный
консольный проект.

**Соответствие нумерации** (в документе — «Задание N», в проекте — `TaskN+11`):

| Задание из `ЛабПарПрограм.docx` | Проект  |
|---------------------------------|---------|
| Задание 1 — Введение в параллельные циклы      | `Lab6/Task12` |
| Задание 2 — `Parallel.ForEach` с коллекциями   | `Lab6/Task13` |
| Задание 3 — PLINQ для анализа данных           | `Lab6/Task14` |
| Задание 4 — Разделение данных и агрегация      | `Lab6/Task15` |
| Задание 5 — Комплексная обработка изображений  | `Lab6/Task16` |

> Если на машине преподавателя только SDK 8.0, нужно заменить
> `<TargetFramework>net10.0</TargetFramework>` на `net8.0` во всех `.csproj`.
> Используемый API доступен и в `net8.0`, кроме `PeriodicTimer` (тоже с .NET 6)
> и `GetWindowedStatistics` — смена TFM безопасна.

## 2. Что показывать преподавателю (по заданиям)

### Задание 1 (`Task12`) — параллельные циклы (≈20 с)

Ключевая таблица (замеры на 8 ядрах):

```
суммарное время lock         : 785 мс
суммарное время Interlocked  : 146 мс
локальный аккумулятор        :  17 мс
```

и сегментированное решето Эратосфена: `348 мс → 57 → 42 → 77 мс`,
ускорение **8.34×**, количество простых во всех вариантах обязано совпасть:
`1 270 607`. Дополнительно показывается потеря обновлений без синхронизации
(≈70 %).

### Задание 2 (`Task13`) — `Parallel.ForEach` (≈15 с)

Покажите разницу `Break()` (обрабатывается всё до точки остановки,
детерминированно) и `Stop()` (досрочная остановка без детерминизма) на числе
обработанных элементов, и работающую отмену через `ParallelOptions`.

### Задание 3 (`Task14`) — PLINQ (≈20 с)

Сравните LINQ и PLINQ: на лёгком предикате PLINQ **проигрывает** (≈0.35×),
на тяжёлой выборке выигрывает (≈2.15×). Покажите
`WithDegreeOfParallelism(4)` и `WithCancellation`.

### Задание 4 (`Task15`) — разделение данных (≈20 с)

Ключевая строка, доказывающая работу локальной очереди разделителя:

```
Пополнений локальной очереди: 180, взято из неё: 540, напрямую из общей: 0
```

Покажите зависимость времени от размера блока (1 / 5 / 15 / 45 / 150 / 900)
и поведение при неравномерной нагрузке.

### Задание 5 (`Task16`) — индивидуальный вариант (по номеру)

```bash
dotnet run -- 1     # большие массивы
dotnet run -- 2     # PLINQ-фильтрация
dotnet run -- 3     # матрицы
dotnet run -- 4     # изображения
dotnet run -- 5     # текст
dotnet run -- 6     # численные методы
dotnet run -- 7     # сортировка и поиск
```

Без аргумента выполняется вариант 1. Для преподавателя важно показать
свой вариант и честно прокомментировать отрицательные результаты:

| Вариант | Что смотреть |
|---------|--------------|
| 1 | ускорение 2.47x за счёт разделимости по индексу |
| 2 | **проигрыш 0.50x** — PLINQ не окупается на лёгких операциях |
| 3 | ускорение 4.10x — строки независимы |
| 4 | ускорение 1.60x / 2.94x, буфер результата отделён от исходного |
| 5 | ускорение 2.15x, каждый диапазон считает в свой словарь |
| 6 | ускорение 2.81x / 4.27x, `double` сравнивается по относительной погрешности |
| 7 | ускорение 1.81x на сортировке, **проигрыш 0.72x** на поиске, QuickSelect в 16x быстрее сортировки |

## 3. Полный прогон (для отчёта)

```bash
cd /home/masqueradis/ssp/Lab6
mkdir -p /tmp/lab6-check
for i in 12 13 14 15; do
  dotnet build -v q --nologo Task$i/Task$i.csproj > /tmp/lab6-check/Task$i.build.log 2>&1
  echo "Task$i build=$?"
  (cd Task$i && timeout 300 dotnet run --no-build < /dev/null > /tmp/lab6-check/Task$i.run.log 2>&1)
  echo "Task$i run=$?"
done
dotnet build -v q --nologo Task16/Task16.csproj > /tmp/lab6-check/Task16.build.log 2>&1
echo "Task16 build=$?"
for v in 1 2 3 4 5 6 7; do
  (cd Task16 && timeout 300 dotnet run --no-build -- $v < /dev/null > /tmp/lab6-check/Task16.v$v.run.log 2>&1)
  echo "Task16/v$v run=$?"
done
```

Ожидается: все `build=0`, все `run=0`, в каждом логе есть строка
`ВЫПОЛНЕНО`.

## 4. Частые проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| `dotnet: command not found` | не установлен .NET SDK; нужен 8.0 или 10.0 |
| Времена отличаются от документации | замеры зависят от машины; **совпадение результатов и количества простых** важно, время — нет |
| PLINQ медленнее LINQ | так и задумано: это один из выводов задания 3 |
| Задание 5 долго работает | массивы и изображения большие; для быстрой проверки берите не свой вариант: `dotnet run -- 1` |
| `Задание 16` выбрало вариант 1 | без аргумента по умолчанию выполняется вариант 1 |
