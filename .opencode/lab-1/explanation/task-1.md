# Задание 1 — Анализ IL-кода базовой конструкции (произведение двух чисел)

**Файл:** `Lab1/Task1/Program.cs`
**Целевая платформа:** .NET 8.0 (SDK 8.0.130)

## Суть задания

Написать простую C#-конструкцию (произведение двух целых чисел), получить её
IL-код, показать его работу и объяснить.

## Код

```csharp
public static int Multiply(int a, int b) => a * b;

public static int MultiplyBlock(int a, int b)
{
    int result = a * b;
    return result;
}
```

Оба метода вычисляют одно и то же, но компилятор генерирует разный IL:
expression-bodied метод (4 байта, 0 локальных) против блочного (11 байт, 2 локальные).

## IL-трассировка

Программа выводит таблицу: адрес → HEX-байт → мнемоника → операция → состояние
стека после каждой инструкции. Пример для `Multiply`:

```
IL-код метода Multiply (4 байт):
  Локальных переменных: 0
  Максимальный размер стека: 8 байт

  Адрес │ HEX │ Мнемоника   │ Операция                        │ Стек
  ──────┼─────┼────────────┼─────────────────────────────────┼──────────
      0 │ 02  │ ldarg.0    │ загрузить аргумент 0 (a)       │ [1]
      1 │ 03  │ ldarg.1    │ загрузить аргумент 1 (b)       │ [2]
      2 │ 5A  │ mul        │ умножить                       │ [1]
      3 │ 2A  │ ret        │ вернуть результат              │ [0]
```

## Объяснение трассировки стека

| Адрес | Байт | Инструкция | Стек до | Стек после | Что происходит |
|-------|------|-----------|---------|------------|----------------|
| 0 | `02` | `ldarg.0` | [] | [a] | загрузить первый аргумент |
| 1 | `03` | `ldarg.1` | [a] | [a, b] | загрузить второй аргумент |
| 2 | `5A` | `mul` | [a, b] | [a×b] | извлечь два, перемножить, положить результат |
| 3 | `2A` | `ret` | [a×b] | [] | вернуть результат вызывающему |

## Почему нет локальных переменных

Expression-bodied метод `=> a * b` не создаёт промежуточных переменных:
аргументы `a` и `b` загружаются на стек напрямую через `ldarg`, результат
`a * b` остаётся на вершине стека и возвращается через `ret`.

В блочном теле компилятор действует иначе:

```
IL-код метода MultiplyBlock (11 байт):
  Локальных переменных: 2
  Максимальный размер стека: 2 байт

  Адрес │ HEX │ Мнемоника   │ Операция                        │ Стек
  ──────┼─────┼────────────┼─────────────────────────────────┼──────────
      0 │ 00  │ nop        │ нет операции                   │ [0]
      1 │ 02  │ ldarg.0    │ загрузить аргумент 0 (a)       │ [1]
      2 │ 03  │ ldarg.1    │ загрузить аргумент 1 (b)       │ [2]
      3 │ 5A  │ mul        │ умножить                       │ [1]
      4 │ 0A  │ stloc.0    │ сохранить в локальную 0        │ [0]
      5 │ 06  │ ldloc.0    │ загрузить локальную 0          │ [1]
      6 │ 0B  │ stloc.1    │ сохранить в локальную 1        │ [0]
      7 │ 2B  │ br.s       │ безусловный переход            │ [0]
      8 │ 00  │ nop        │ нет операции                   │ [0]
      9 │ 07  │ ldloc.1    │ загрузить локальную 1          │ [1]
     10 │ 2A  │ ret        │ вернуть результат              │ [0]
```

Компилятор в Debug-режиме создаёт 2 локальные переменные:
- локальная 0 — `result` (результат умножения)
- локальная 1 — временная для возвращаемого значения

Инструкции `nop` и `br.s` — отладочный «шум», в Release-режиме их может не быть.

## Максимальный размер стека

Для `Multiply`: `MaxStackSize = 8` — это 2 значения `int` по 4 байта
(оба аргумента на стеке одновременно перед `mul`).

Для `MultiplyBlock`: `MaxStackSize = 2` — компилятор не держит больше
одного значения на стеке, потому что промежуточные результаты идут
через локальные переменные.

## Вывод

IL — стековая машина. Выбор между expression-bodied и блочным телом влияет
на количество IL-инструкций, число локальных переменных и максимальный размер
стека.
