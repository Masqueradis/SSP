# Задание 5 — Профилирование и оптимизация

**Файл:** `Lab1/Task5/Program.cs`
**Целевая платформа:** .NET 8.0

## Суть задания

Сравнить производительность разных способов вызова кода и проанализировать
скомпилированный JIT-метод.

## 1. Инспекция метода

```csharp
RuntimeHelpers.PrepareMethod(m.MethodHandle);
Console.WriteLine($"Адрес метода Add: 0x{m.MethodHandle.GetFunctionPointer().ToInt64():X}");
```

- `PrepareMethod` принудительно JIT-компилирует метод;
- `GetFunctionPointer()` возвращает адрес скомпилированного машинного кода в памяти.

## 2. IL-трассировка

Программа декомпилирует IL-байты `Calculator.Add` в таблицу: адрес → HEX →
мнемоника → операция → стек.

### Результат

```
Адрес метода Add: 0x7205B3699038

IL-код метода Calculator.Add (4 байт):
  Локальных переменных: 0
  Максимальный размер стека: 8 байт

  Адрес │ HEX │ Мнемоника   │ Операция                        │ Стек
  ──────┼─────┼────────────┼─────────────────────────────────┼──────────
      0 │ 03  │ ldarg.1    │ загрузить a                    │ [1]
      1 │ 04  │ ldarg.2    │ загрузить b                    │ [2]
      2 │ 58  │ add        │ сложить                        │ [1]
      3 │ 2A  │ ret        │ вернуть результат              │ [0]
```

Ключевое отличие от `Multiply`: `add` вместо `mul`, и `ldarg.1`/`ldarg.2`
(а не `ldarg.0`/`ldarg.1`), потому что `Calculator` — нестатический класс:
аргумент 0 = `this`, `a` = индекс 1, `b` = индекс 2.

## 3. Сравнение способов вызова (10 000 000 итераций `x + y`)

| Способ вызова       | Время  | Накладные расходы                       |
|---------------------|--------|-----------------------------------------|
| Прямой (встроенный) | 24 мс  | JIT может инлайнить код                 |
| Статический метод   | 55 мс  | стоимость самого вызова                 |
| Делегат             | 55 мс  | косвенный вызов (indirect call)         |
| Виртуальный метод   | 56 мс  | диспетчеризация через vtable            |

### Результат

```
Прямой вызов: 24 мс
Статический метод: 55 мс
Делегат: 55 мс
Виртуальный метод: 56 мс
```

## Вывод

- прямой вызов быстрее всех — JIT-оптимизатор (в т. ч. инлайнинг) применяется к
  типизированным прямым вызовам;
- делегат и виртуальный вызов платят фиксированную цену за динамическую
  диспетчеризацию;
- `ldarg.0` для нестатического метода — это всегда `this`, поэтому параметры
  начинаются с индекса 1.
