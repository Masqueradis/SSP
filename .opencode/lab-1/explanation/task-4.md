# Задание 4 — Исследование JIT-компиляции

**Файл:** `Lab1/Task4/Program.cs` (метод `CreateDynamicSum`)
**Целевая платформа:** .NET 8.0

## Суть задания

Оценить влияние JIT-компиляции на скорость программы на примере сложения
элементов массива из **10000 целых чисел** — с JIT и без него.

JIT-компиляция выполняется **один раз при первом вызове метода**: в этот момент IL
переводится в машинный код. Далее метод исполняется из скомпилированного кода.

## Три замера

1. **Первый вызов** `SumCold(arr)` — ещё ни разу не компилировался, поэтому по
   времени включает JIT-компиляцию + выполнение. Точность через
   `Stopwatch.GetTimestamp()` в микросекундах.

2. **100000 вызовов** `Sum(arr)` после однократного прогрева — код уже
   скомпилирован, замеряется среднее время **одного** «тёплого» вызова.

3. **200 свежих `DynamicMethod`** — каждый вызов `CreateDynamicSum()` рождает новый
   метод, требующий собственной JIT-компиляции. Показывает стоимость повторной
   компиляции.

## Результат выполнения

```
Первый вызов (JIT): 285 мкс, сумма 4971968
100000 вызовов после компиляции: 2524 мс
Среднее время вызова: 25.25 мкс
200 новых DynamicMethod (каждый со своим JIT): 19 мс
Среднее время создания с компиляцией: 97 мкс
```

## Вывод

- первый («холодный») вызов ~280 мкс против ~25 мкс «тёплого» — разница и есть
  стоимость JIT-компиляции IL в машинный код;
- каждое создание нового `DynamicMethod` (со своей компиляцией) занимает ~100 мкс,
  что подтверждает: JIT срабатывает заново для каждого ещё не скомпилированного
  метода;
- .NET сочетает переносимый IL и JIT, который генерирует машинный код под
  конкретный процессор во время выполнения.
