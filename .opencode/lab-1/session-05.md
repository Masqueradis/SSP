# Сессия 05 — Подробный IL-разбор с трассировкой стека

## Дата
07 сентября 2026

## Поставленные задачи

Добавить в Task1 и Task5 подробный вывод IL-информации при запуске программы:
пошаговую декомпиляцию каждого байта (HEX → мнемоника → описание → стек),
объяснение отсутствия локальных переменных, сравнение expression-bodied и
блочного тел.

## Что было сделано

### Task1/Program.cs

1. Добавлен метод `Trace(byte[] il, MethodBody body)`, выводящий таблицу:
   адрес | HEX | мнемоника | описание операции | стек после.

2. Добавлен метод `MultiplyBlock(int a, int b)` с блочным телом
   (`int result = a * b; return result;`), IL которого имеет 11 байт и 2
   локальные переменные (в отличие от 4 байт и 0 локальных у Multiply).

3. Добавлено объяснение в конце программы:
   - expression-bodied: 4 байта, 0 локальных, стек напрямую;
   - блочное тело: 11 байт, 2 локальные, nop/br.s отладочный шум.

4. Метод `Trace` декодирует опкоды: nop (0x00), ldarg.0-2 (0x02-0x04),
   ldloc.0-1 (0x06-0x07), stloc.0-1 (0x0A-0x0B), ldc.i4.1 (0x16),
   call (0x28), ret (0x2A), br.s (0x2B), blt.s/ble.s (0x2D-0x2E),
   add (0x58), mul (0x5A), sub (0x5B).

5. Стек отслеживается по ходу выполнения: ldarg/ldloc увеличивают,
   mul/add/sub/stloc/ret уменьшают.

### Task5/Program.cs

1. Добавлен аналогичный метод `Trace(byte[] il, MethodBody body, MethodInfo method)`
   с определением имён параметров через `method.GetParameters()`.

2. Для виртуального метода `Calculator.Add` отображается:
   ldarg.0 = this, ldarg.1 = a, ldarg.2 = b (индекс сдвинут на 1 из-за
   неявного параметра this).

3. Таблица декомпиляции выводится перед профилированием.

### Исправление ошибки

Изначально в Task5 opcodes ldarg.0/ldarg.1 выводились как «a»/«b» — неверно
для виртуального метода. Исправлено: метод принимает MethodInfo и определяет
первый индекс по `method.IsStatic`.
