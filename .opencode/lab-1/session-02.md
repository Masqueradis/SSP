## Задание 1 — Анализ IL-кода (произведение двух чисел)

**Файл:** `Lab1/Task1/Program.cs`, утилита `Task1/`.

Код:
```csharp
static int Multiply(int a, int b) => a * b;
```

Метод `AnalyzeIL` через `MethodInfo.GetMethodBody()` и `GetILAsByteArray()`
выводит размер IL, локальные переменные, максимальный стек и HEX-представление.

**Результат выполнения:**
```
=== Задание 1: Анализ IL-кода базовой конструкции ===

Произведение двух чисел: 15 * 7 = 105

│ Анализ: Произведение двух чисел (Multiply) │
Размер IL: 4 байт
Локальные переменные: 0
Максимальный размер стека: 8

IL-инструкции (HEX):
02 03 5A 2A
```

**Объяснение байт-кода:**
- `02` — `ldarg.0`: загрузить аргумент `a` в стек;
- `03` — `ldarg.1`: загрузить аргумент `b` в стек;
- `5A` — `mul`: умножить два верхних значения стека;
- `2A` — `ret`: вернуть результат из вершины стека.

Размер IL 4 байта (4 инструкции), локальных переменных нет (аргументы в стеке),
макс. стек 8 (2 значения по 4 байта).

## Задание 2 — Работа с IL-генератором

**Файлы:** `Lab1/Task2/ILGeneratorDemo.cs`, `Lab1/Task2/Program.cs`.

### 2.1 Рекурсивное вычисление n!

Через `DynamicMethod` + `ILGenerator` (метод вызывает сам себя через
`il.Emit(OpCodes.Call, dynamicMethod)`):
- `if (n <= 1) return 1;`
- `else return n * Factorial(n - 1);`

Логика в IL: `ldarg.0; ldc.i4.1; ble end` → `ldarg.0; ldarg.0; ldc.i4.1; sub; call Factorial; mul; ret` → `end: ldc.i4.1; ret`.

### 2.2 Максимум из трёх чисел

Алгоритм: `max = a`; `if (max < b) max = b`; `if (max < c) max = c`; `return max`.
Использованы метки `setB`, `setC`, `end`.

**Результат выполнения:**
```
Рекурсивное вычисление n! через DynamicMethod + ILGenerator:
  0! = 1
  1! = 1
  2! = 2
  3! = 6
  4! = 24
  5! = 120
  6! = 720
  7! = 5040

Максимум из трёх чисел через DynamicMethod + ILGenerator:
  Max(3, 7, 5)   = 7
  Max(-1, -5, -2) = -1
  Max(9, 2, 9)   = 9
```

## Задание 4 — Исследование JIT-компиляции

**Файл:** `Lab1/Task4/Program.cs`.

Сценарии (массив из 10000 целых чисел, `Random(42)`):
- **A. Холодный старт** — первый вызов `SumArrayCold` (JIT-компиляция + выполнение),
  измеряется через `Stopwatch.GetTimestamp()` с наносекундной точностью.
- **B. Тёплый старт** — после прогрева 100000 вызовов `SumArray` (код уже скомпилирован).
- **C. Многократный JIT** — каждый новый `DynamicMethod` требует отдельной JIT-компиляции
  (`DynamicSumFactory.Create()`), генерация тела через `ILGenerator` (`ldelem.i4`, `add`, ...).

**Результат выполнения:**
```
Массив из 10000 целых чисел. Повторных вызовов: 100,000

Сценарий A: «Холодный старт» (первый вызов = JIT-компиляция + выполнение)
  Результат: 4,971,968
  Время первого вызова: 269178 нс

Сценарий B: «Тёплый старт» (метод уже скомпилирован JIT)
  Результат: 4,971,968
  100,000 вызовов: 2449 мс
  Среднее время вызова: 24490.3 нс

Сценарий C: пересоздание метода через DynamicMethod (каждый раз JIT заново)
  200 созданий+вызовов: 13734 мкс суммарно
  Среднее время на создание с JIT: 68668 нс

--- Сравнение ---
  Холодный старт (JIT, 1 вызов):     269178 нс
  Тёплый вызов (без JIT):           24490.3 нс
  Отношение холодный/тёплый:     11.0x
```

**Вывод:** JIT-компиляция выполняется однократно при первом вызове. Первый (холодный)
вызов в ~10 раз дороже из-за компиляции IL в машинный код; последующие (тёплые)
вызовы исполняются из готового машинного кода. Каждая новая `DynamicMethod` влечёт
свою компиляцию (~68 мкс в среднем).

## Задание 5 — Профилирование и оптимизация

**Файл:** `Lab1/Task5/Program.cs` (классы `JitVisualization`, `Calculator`, `Program`).

- `JitVisualization.InspectMethod` — через `RuntimeHelpers.PrepareMethod`,
  `MethodHandle.GetFunctionPointer()` выводит адрес скомпилированного метода то кода,
  размер IL, локальные переменные, максимальный стек и атрибуты (virtual/static/...).
  Для `InlinedAdd` и `Calculator.Add` получены адреса вида `0x00007D56EAD93138`.
- `JitVisualization.CompareJitModes` — проверяет, включена ли Tiered Compilation,
  сообщает, как её изменить (`<TieredCompilation>false</TieredCompilation>` или
  `DOTNET_TieredCompilation=0`).
- Профилирование 10 000 000 итераций `x + y` четырьмя способами.

**Результат (Debug, TieredCompilation включена, .NET 8.0.130):**
```
TieredCompilation: ВКЛЮЧЕНА

Адрес метода: 0x00007D56EAD93138   (InlinedAdd)
Адрес метода: 0x00007D56EAFD94B8   (Calculator.Add)

Количество итераций: 10,000,000

Прямой вызов (локальный):            24 мс
Прямой вызов статического метода:     53 мс
Через делегат:                       55 мс
Через виртуальный метод:             70 мс
```

**Вывод:** прямой (встроенный) вызов быстрее всего — JIT способен инлайнить код.
Делегат (indirect call) и виртуальный метод (dynamic dispatch) медленнее. Тот же
прогон с `DOTNET_TieredCompilation=0` дал близкие значения (~24/53/55/69 мс), т.к.
методы простые и уже достигли оптимизированного уровня.
